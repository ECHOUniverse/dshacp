第 1 课：在 Zed 中跑通 DSHACP（首次对话）

这一课的目标只有一个：在 Zed 里跟 DSH 的 agent 说上话，看到文字流式出现。 做完这一课，你就有了一个看得见的胜利，后面的功能验证都是在这个基础上加料。

背景：你在做什么

Zed 通过 ACP 协议（一个标准，相当于 AI 编辑器和 agent 之间的"电话线协议"）跟外部 agent 通信。 你的 dshacp 就是这条电话线的"服务端"——Zed 负责拨号（启动进程、发消息），dshacp 负责接听（跑 DeepSeek 模型、执行工具、回传结果）。 官方文档：Zed 外部代理文档。

前置检查（30 秒）

打开"终端"App（Spotlight 搜 Terminal），逐条输入：

node --version          # 应显示 v22 或更高
ls ~/.dsh/.credentials.yaml   # 应显示文件存在（里面有 DEEPSEEK_API_KEY）
ls /Applications/Zed.app      # 应显示 Zed 已安装
你的机器这三条都已满足（我已帮你查过），可以直接进入下一步。

步骤 1：让 dshacp 命令全局可用（终端）

Zed 配置里写 "command": "dshacp"，意思是让系统去 PATH 里找这个命令。 它还没被"安装"到 PATH 里，我们用 npm link 把它挂上去（在项目目录里执行）：

cd /Volumes/WD-1T/00_Workspace/00_Active/CodeProject/DSHACP
npm run build      # 确保 lib/ 是最新的（你已经构建过，可跳过）
npm link           # 把 dshacp 命令链接到全局

验证链接成功：

which dshacp       # 应输出一个路径，如 /usr/local/bin/dshacp
dshacp --help      # 应显示用法说明（dshacp 是 stdio 服务，不是交互式 CLI，参数只有 --config 和 --help）
成功：which dshacp 输出路径，没有 "command not found"。
失败：显示 command not found → 检查是否在项目目录执行了 npm link，或询问老师。

步骤 2：先不依赖 Zed，单独验证服务端活着（终端）

这个步骤很关键：先排除服务端问题。如果这里能通，后面 Zed 连不上就一定是配置问题。 在终端运行下面这行（一条命令，直接粘贴回车）：

printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":1,"clientCapabilities":{},"clientInfo":{"name":"manual-test","version":"0.0.1"}}}' | dshacp

这条命令的意思：手动给 dshacp 发一条 ACP 的 initialize 消息（协议握手），然后它应该回一条 JSON 回应。

成功：屏幕上出现一行以 {"jsonrpc":"2.0","id":1,"result":{...}} 开头的 JSON， 里面能看到 "loadSession":true 和 "authMethods":[]。看到这个就说明服务端完全正常。
失败：报错或没有输出 → 服务端有问题，先解决它再继续（把报错贴给老师）。
按 Ctrl+C 结束这条命令（它不会自己退出，是正常的——它在等你继续说话）。

步骤 3：在 Zed 设置里注册 DSH agent

Zed 的配置文件在 ~/.config/zed/settings.json。我们用最直观的方式：让 Zed 自己打开设置。

  1. 打开 Zed（点 Dock 里的 Zed 图标）
  2. 打开设置：按 ⌘+,（逗号键）， 或者按 ⌘+Shift+P 打开命令面板，输入 zed: open settings 回车。 会打开一个 settings.json 编辑器标签页。
  3. 找到 agent_servers 块：滚动找到 "agent_servers": {。 你里面已经有一个 "pi-acp" 条目。在它后面（注意逗号）加一个新条目：

    把下面这段插到 "agent_servers": { 的 { 之后、"pi-acp" 之前： 
        "DSH": {
      "type": "custom",
      "command": "dshacp",
      "args": [],
      "env": {}
    },
    完成后 agent_servers 部分看起来像这样： 
      "agent_servers": {
    "DSH": {
      "type": "custom",
      "command": "dshacp",
      "args": [],
      "env": {}
    },
    "pi-acp": {
      "default_config_options": { "thought_level": "xhigh" },
      "type": "registry"
    }
  }
  4. 保存：⌘+S。
  5. 重启 Zed：⌘+Q 完全退出，再重新打开。 这一步很重要——agent 服务器列表在启动时读取，热保存不一定生效。
三个字段的含义：type: "custom" 表示"我自己写的 agent"（必填，官方文档示例容易漏）； command: "dshacp" 是要启动的程序；env: {} 是额外环境变量——密钥不写这里， dshacp 自己会读 ~/.dsh/.credentials.yaml。参考：官方文档。

步骤 4：新建 DSH 线程，开始对话 🎉

  1. 打开 Agent 面板：按 ⌘+Shift+P， 输入 agent: new thread 回车。或者点窗口右下角状态栏的 ✨ 图标。
  2. 选择 agent：在新线程的 agent 选择菜单里，选择 DSH （如果没看到，也可以命令面板输入 agent: new external agent thread，选择 DSH）。
  3. 发送第一条消息：在下方的输入框输入： 
    你好，请用一句话介绍你自己，然后说出当前工作目录里有什么。
    按回车发送。
成功的样子：
  • 输入框上方出现 agent 的回复，文字一个字一个字地冒出来（流式输出）
  • 可能先出现一段灰色/斜体的"思考"内容，然后才是正式回复
  • 如果它调用了工具（比如读取目录），会出现一个可展开的工具卡片
失败的样子（按优先级排查）：
  • 选不到 DSH：settings.json 没保存/没重启 → 回到步骤 3 检查
  • 发送后立刻报错 "Failed to start agent"：dshacp 命令不可用 → 回到步骤 1 检查 which dshacp
  • 发送后转圈很久然后报错：模型密钥问题 → 确认 ~/.dsh/.credentials.yaml 里有 DEEPSEEK_API_KEY
  • 其他情况：把错误信息告诉我（老师），或者用第 3 课的方法看 ACP 日志

课后巩固（2 分钟，强烈建议）

在同一线程里继续发：

请运行 pwd 命令，告诉我输出，然后创建一个名为 zed-test.txt 的文件，内容写 "hello from dshacp"。

观察三件事：

  1. 工具卡片：出现 bash 工具卡片（显示命令），完成后卡片显示结果
  2. 文件真的被创建：在 Zed 左侧文件树里能看到 zed-test.txt（如果没看到，刷新文件树）
  3. 回复内容：agent 会汇报它做了什么

这一条消息同时验证了：工具调用、工具结果渲染、真实文件写入。全部看到就算过关。
